# ADR-003：V1 交互界面策略

**状态：** 已接受（Accepted）
**日期：** 2026-09-29
**决策者：** 项目决策人（先生）

## 结论

> **V1 采用 CLI + 文件目录作为主要交互入口；Local Web UI 延后至 V1.1/V2。**

V1 坚决不做 Web UI。

## 上下文

V1 需要证明的核心是：

```text
Task → Queue → Browser → ChatGPT → Download → Artifact → Gate → Next Task
```

而不是「会不会画网页」。早期数据模型（Project / Task / StageRun / Artifact / Defect / Revision）每改一次，Web UI 都会「后端改一次 + API 改一次 + 前端改一次」，非常浪费。

## 决策

V1 CLI 至少覆盖以下命令：

```bash
pwm project create
pwm run project_A
pwm watch project_A
pwm status project_A
pwm retry TASK_0012
pwm resume project_A
pwm rollback project_A --to 07B
pwm inspect TASK_0012
```

终端 `status` 输出目标：

```text
PPT Workflow Manager

Project    : 精品课_友谊号列车
Stage      : 07B
Page       : MISSION_07
Object     : CHAR_MISSION_07_CRAB

Queue
--------------------------------
Pending     16
Running      1
Completed   83
Failed       2

Current Task
--------------------------------
TASK-07B-0084
Waiting for ChatGPT...
```

## 何时上 Web UI

```text
V1       CLI
V1.1/V2  Local Web UI
```

待 Project / Task / StageRun / Artifact / Defect / Revision 等数据模型稳定后，再套 Web 界面。

## 后果

- **正面**：迭代快，无前端同步成本；CLI 输出天然适合脚本化与日志留痕。
- **负面**：非技术用户操作门槛略高；后续做 Web 时需补一层展示层（届时数据模型已稳定，成本低）。
