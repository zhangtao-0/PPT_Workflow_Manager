# PPT Workflow Manager V1 — 任务分解与实施计划

> 依据：《PPT_Workflow_Manager_V1_完整产品与技术设计方案.md》（V1 设计基线）
> 用途：作为研发排期、任务拆分、验收的依据。任务粒度对齐设计方案的 Stage 00–10 与 Phase A–G。
> 技术栈基线：Python 3.13（核心 Workflow Engine / Adapter / Registry / Gate），Playwright 驱动 ChatGPT 网页端，YAML/JSON 作为事实文件，V1.0 暂缓 SQLite。

---

## 0. 分解原则

1. **对齐 Phase A–G**：设计方案的推荐实施顺序（第 22 节）是本次任务分解的骨架，保证「先搭骨架、再接 ChatGPT、后落地 07B」。
2. **对齐 MVP 边界**：第 21.1 节「必须完成（MVP）」22 项必须全部覆盖；第 21.2 节「可延后」项明确标记为 V1.x / V2。
3. **任务可验收**：每个任务给出「完成定义（DoD）」，引用设计方案第 23 节的关键验收测试。
4. **Governance 与 Execution 分离**：任务同时覆盖 `governance/`（机器可读规范）与 `app/`（执行引擎）两条线。

## 2. Phase A｜骨架（不碰 ChatGPT DOM）

### 任务 A1：数据模型定义
- **内容**：实现 Project / StageRun / Page / PageMapping / ObjectSpec / Task / Artifact / ArtifactRelation / Batch / GateResult / Defect / Revision 的 Pydantic 或 dataclass 模型（对齐 §4）。
- **产出**：`app/workflow/models.py`
- **DoD**：所有模型可被 JSON/YAML 序列化与反序列化；字段与 §4 示例一一对应。

### 任务 A2：Project Manager
- **内容**：创建/加载 Project，生成 `project_id`，初始化目录（对齐 §5 单项目结构），写 `project.yaml` 与 `state.json`。
- **产出**：`app/workflow/project.py`
- **DoD**：`pwm project init --name 友谊号列车` 能生成完整项目目录与初始状态。

### 任务 A3：Artifact Registry
- **内容**：Artifact 的登记、查询、版本化（accepted / superseded / rejected），Hash/Dedup（对齐 §11）。
- **产出**：`app/registry/registry.py`
- **DoD**：可登记 Artifact、按 object_id 查询最新 accepted 版本、supersede 不覆盖旧文件。

### 任务 A4：Stage Definition Loader
- **内容**：加载 `governance/stages/*.yaml`，解析 prerequisites / inputs / outputs / validators / retry / rollback（对齐 §14）。
- **产出**：`app/workflow/stage_loader.py` + `governance/stages/` 下的 Stage YAML 骨架
- **DoD**：能从 YAML 读取 Stage 定义并实例化，不硬编码任何 Stage 流程。

### 任务 A5：Task Queue
- **内容**：Task 状态机（PENDING→READY→RUNNING→…→COMPLETED，及异常分支）、单并发调度、优先级（对齐 §9）。
- **产出**：`app/queue/queue.py`
- **DoD**：P0 修复 > Gate Block > 当前 Stage > 后续预生成 的优先级正确；默认并发 1。

### 任务 A6：Gate Validator 接口
- **内容**：通用 Validator 与 PPT 专用 Validator 的注册与执行（对齐 §15.1/15.2）。
- **产出**：`app/gates/validator.py` + `app/gates/validators/`
- **DoD**：`file_exists` / `unique_id` / `expected_count_match` 等机器 Gate 可运行。

### 任务 A7：Retry / Rollback 接口
- **内容**：Retry 与 Rollback 分离的控制器接口；Rollback 采用 Selective Rebuild 语义（对齐 §2.8 / §6.6 / §9.3）。
- **产出**：`app/rollback/controller.py`
- **DoD**：能标记受影响 Artifact 为 superseded/invalidated，生成新上游 StageRun，不默认全项目重跑。

### 任务 A8：FakeAdapter 端到端测试
- **内容**：实现 FakeAdapter，模拟 Stage 00→07B 全链路，验证状态与目录生成正确（对齐 §22 Phase A 验收）。
- **产出**：`app/adapters/fake.py` + `tests/test_e2e_fake.py`
- **DoD**：不访问网页，从 Stage 00 跑到 07B，生成正确状态和目录（§23.1/§23.3）。

## 3. Phase B｜ChatGPT 基础能力

### 任务 B1：浏览器接管与会话管理
- **内容**：Playwright + CDP 接管已登录浏览器，新建/打开聊天，会话恢复（对齐 §10.1/§10.3）。
- **产出**：`app/adapters/chatgpt/session.py`
- **DoD**：能 attach 已登录 Chrome/Edge，new/continue 会话，程序不保存密码。

### 任务 B2：Selector 隔离
- **内容**：所有 DOM selector 集中到 `app/adapters/chatgpt/selectors.py`（对齐 §10.2）。
- **产出**：`app/adapters/chatgpt/selectors.py`
- **DoD**：业务代码不直接引用网页 selector。

### 任务 B3：文件上传与文本发送
- **内容**：upload_files / send_text / submit（对齐 §3.3 ChatAdapter 抽象）。
- **产出**：`app/adapters/chatgpt/chat.py`
- **DoD**：可上传文件并发送文本，拿到回复。

### 任务 B4：回复完成检测
- **内容**：wait_until_complete / get_response_text，处理 DOM 变化与超时（对齐 §10.3）。
- **产出**：`app/adapters/chatgpt/chat.py`
- **DoD**：能判断回复是否完成，并取回完整文本。

### 任务 B5：ChatAdapter 统一接口
- **内容**：实现 §3.3 的 `ChatAdapter` 抽象基类，ChatGPTAdapter 继承。
- **产出**：`app/adapters/base.py` + `app/adapters/chatgpt/__init__.py`
- **DoD**：业务代码只依赖抽象接口，不感知平台。

### 任务 B6：闭环验收
- **内容**：一个普通图片/文档任务 Task→ChatGPT→本地 Artifact 完整闭环（对齐 §22 Phase B 验收）。
- **产出**：`tests/test_chatgpt_loop.py`（可选跳过/手动）
- **DoD**：能完成一轮真实对话闭环。

## 4. Phase C｜图片 Task Boundary 与下载

### 任务 C1：Task Boundary 快照
- **内容**：任务发送前/后记录 assistant turn 数、可下载资源标识、图片集合、conversation id（对齐 §10.4）。
- **产出**：`app/adapters/chatgpt/boundary.py`
- **DoD**：能精确区分「本轮新增」与「历史资源」。

### 任务 C2：Download Collector
- **内容**：snapshot→send→wait→snapshot→diff→download→hash/dedup→register（对齐 §10.5）。
- **产出**：`app/adapters/chatgpt/downloader.py`
- **DoD**：连续 5 个图片任务不串任务、不重复下载（§23.4）。

### 任务 C3：Artifact 自动注册
- **内容**：下载资源自动计算 hash 并登记 Artifact（对齐 §11）。
- **产出**：集成到 `app/registry/`
- **DoD**：下载完成不等于 Task 完成，仍需过 Output Contract / Gate。

### 任务 C4：下载边界测试
- **内容**：§23.4 下载边界测试落地。
- **产出**：`tests/test_boundary.py`
- **DoD**：同对话 30 张历史图，新任务 2 张，只下载新资源。

### 任务 C5：Hash 与 Dedup 加固
- **内容**：跨任务去重，防止 Work 重复生成（对齐 §11.2）。
- **产出**：`app/registry/dedup.py`
- **DoD**：相同内容不重复登记/下载。

## 5. Phase D｜Stage 07B 先落地

### 任务 D1：07B Object 队列编排
- **内容**：读取 locked ObjectSpec，找最小未完成 sequence，逐对象单 Task 执行（对齐 §7 Stage 07B Task）。
- **产出**：`app/workflow/orchestrators/stage_07b.py`
- **DoD**：一个 Object = 一个 Task = 一个独立文件；禁素材总表/拼图（§26 基线 5/6）。

### 任务 D2：单图 Gate
- **内容**：文件名与 Object ID 一致、单对象、Alpha、无背景污染等 Object Gate（对齐 §7 07B Object Gate）。
- **产出**：`app/gates/validators/object_gate.py`
- **DoD**：§23.2 单对象测试通过。

### 任务 D3：批次说明与 ZIP
- **内容**：Batch 管理、batch_notes、ZIP 打包（对齐 §7 07B Batch Gate）。
- **产出**：`app/workflow/orchestrators/batch.py`
- **DoD**：批次 ZIP 不以拼图代替独立图片。

### 任务 D4：断点恢复
- **内容**：程序重启后从最小未完成 Object ID 继续（对齐 §9.4）。
- **产出**：`app/workflow/recovery.py`
- **DoD**：§23.3 断点恢复测试通过。

### 任务 D5：07B YAML 定义落地
- **内容**：把 §14 的 07B 机器可读定义写入 `governance/stages/07B.yaml`。
- **产出**：`governance/stages/07B.yaml`
- **DoD**：引擎只读配置，不硬编码 07B 流程。

### 任务 D6：07B 验收测试
- **内容**：§23.2/§23.3/§23.4 落地为自动化测试。
- **产出**：`tests/test_stage_07b.py`
- **DoD**：10 个 Object 生成 10 个独立文件。

## 9. 里程碑与依赖关系

```text
M1（Phase A 完成）→ 骨架可跑，FakeAdapter 全链路
    ↓
M2（Phase B+C 完成）→ ChatGPT 真实闭环 + 图片下载
    ↓
M3（Phase D 完成）→ Stage 07B 独立高清素材生产可用（首个价值点）
    ↓
M4（Phase E 完成）→ Stage 01–07A 全链路
    ↓
M5（Phase F+G 完成）→ Work Handoff + Repair + 最终交付 = V1 完整
```
